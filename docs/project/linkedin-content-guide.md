# LinkedIn Content Guide - Sigloch Consulting

Template und Stilbeschreibung für Blog-Artikel und LinkedIn-Postings.

---

## LinkedIn Guidelines 2025/2026 (Recherche)

### Post vs. Artikel - Entscheidungsmatrix

| Kriterium | Post | Artikel |
|-----------|------|---------|
| **Zeichenlimit** | 3.000 | ~125.000 |
| **Optimale Länge** | 1.300-1.600 | 1.500-2.000 Wörter |
| **Google-Indexiert** | Nein | Ja (SEO-Vorteil) |
| **Feed-Sichtbarkeit** | Hoch | Niedrig (muss als Post geteilt werden) |
| **Formatierung** | Keine native Bold/Italic | Headlines, Bold, Italic, Listen |
| **Personen taggen** | Ja | Nein |
| **Empfehlung** | Engagement, schnelle Reichweite | Thought Leadership, Langform |

**Wann Post?** Kurze Insights, Fragen, Diskussionen, Ankündigungen
**Wann Artikel?** Tiefgehende Analysen, Tutorials, Referenz-Content für SEO

### Post-Struktur (optimal)

```
[HOOK - max 140 Zeichen, vor "See more"]

[BODY - 800-1.200 Zeichen]
- Kernaussage
- 2-3 unterstützende Punkte
- Konkretes Beispiel/Zahl

[CTA - Frage oder Aufforderung]

[HASHTAGS - 3-5, am Ende]
```

**Wichtig:** Link im **ersten Kommentar** posten, nicht im Post-Text!
LinkedIn-Algorithmus bestraft externe Links im Hauptpost.

### Bild-Spezifikationen

| Format | Dimensionen | Verwendung |
|--------|-------------|------------|
| Landscape | 1200 × 627 px | Standard, Link-Preview |
| Square | 1080 × 1080 px | Carousel, Mobile-optimiert |
| Portrait | 1080 × 1350 px | Maximale Feed-Präsenz |

- **Dateityp:** PNG (Grafiken), JPG (Fotos)
- **Max Größe:** 5 MB
- **GIF:** Nicht unterstützt (wird statisch)
- **Anzahl:** 1-9 Bilder pro Post, 1 optimal für Engagement

### Hashtag-Strategie

- **Anzahl:** 3-5 optimal (mehr schadet der Reichweite)
- **Platzierung:** Am Ende des Posts
- **Mix:** 1-2 breite (#KI, #AI) + 2-3 spezifische (#Datenreife, #MBSE)

## Beitragstypen

### Fachbeitrag (Theorie)
**Fokus:** Konzepte, Methoden, Frameworks, Studien
**Ziel:** Thought Leadership, Expertise demonstrieren
**Beispiele:** Datenreife-Serie, Think AI-Serie, Summer School

**Merkmale:**
- Beginnt mit These oder Problemstellung
- Referenziert Studien/Quellen (McKinsey, INCOSE, etc.)
- Strukturierte Argumentation mit Leveln/Stufen
- Abstrakte Konzepte mit konkreten Beispielen
- Endet mit Handlungsempfehlung oder Fazit

### Praxisbeitrag (Anwendung)
**Fokus:** Konkrete Projekte, Tools, Erfahrungsberichte
**Ziel:** Nahbarkeit, "Machen statt Beraten" zeigen
**Beispiele:** Vibe Coding, MCP-Server, ImPhoto, ClaudeGraph

**Merkmale:**
- Beginnt mit konkretem Auslöser/Problem
- Enthält Zahlen: Zeitaufwand, Kosten, Codezeilen
- Persönlicher Ton ("Ich habe...", "Hat natürlich nicht geklappt...")
- Lessons Learned / Key Takeaways
- Oft mit Links zu GitHub, Demos, Prompts

## Textstil

### Struktur
- **Kurze Absätze:** 2-4 Sätze max
- **Fettdruck:** Kernaussagen hervorheben
- **Listen:** Für Aufzählungen und Schritte
- **Zitate:** Als Blockquote für provokante Thesen
- **Tabellen:** Für Vergleiche, Zeitaufwände, Kosten

### Tonalität
- **Direkt:** Keine Füllwörter, keine Marketingfloskeln
- **Persönlich:** "Ich", "Wir", direkte Ansprache "Sie"
- **Selbstironisch:** Eigene Fehler eingestehen ("Hat natürlich nicht funktioniert")
- **Provokant:** Steile Thesen aufstellen, dann belegen
- **Pragmatisch:** Fokus auf Nutzen, nicht auf Perfektion

### Sprachliche Muster
```
"Die Realität ist ernüchternd: ..."
"Was bedeutet das?"
"Meine These ist: ..."
"Der entscheidende Punkt: ..."
"Brutal ehrlich: ..."
"Haben Sie auch so eine Idee?"
"Versuch macht klug."
```

### Vermeiden
- Marketingsprache ("revolutionär", "game-changer")
- Übertriebene Superlative
- Lange Einleitungen
- Passive Formulierungen
- Anglizismen ohne Mehrwert

## Bildstil

### Charakteristik
- **KI-generiert:** Erkennbar, aber funktional
- **Technisch-abstrakt:** Graphen, Netzwerke, Datenstrukturen
- **Farbpalette:** Blau-Töne, Orange-Akzente, dunkle Hintergründe
- **Stil:** Futuristisch, aber nicht kitschig

### Typen
1. **Konzeptbilder:** Abstrakte Darstellungen von Datenflüssen, Netzwerken
2. **Persönliche Bilder:** Profilbild für Autorenzuordnung
3. **Screenshots:** Echte Tool-Outputs, Code-Snippets
4. **Infografiken:** Einfache Diagramme, Tabellen als Bild

### Selbstironie bei Bildern
```
"P.S. Bilderstellung ist NICHT meine Kernkompetenz :-)"
"Die Generierung eines Bildes 'Begeisterter Ingenieur mit kleiner Sorgenfalte' erspare ich mir"
```

## Frontmatter-Schema

```yaml
---
title: 'Serie #N: Prägnanter Titel'
description: 'Max 160 Zeichen. Kernaussage + Nutzenversprechen.'
pubDate: YYYY-MM-DD
author: 'Andreas Sigloch'
image: '/images/XXXXX.jpeg'  # Optional
tags: ['Haupttag', 'KI', 'Weitere Tags']
series: 'Serienname'  # Optional
draft: false
type: 'blog'  # blog | linkedin | conference
linkedinStatus: 'planned'  # draft | planned | published
linkedinType: 'post'  # post | article (default: post)
linkedinHook: ''  # Optional: Manueller Hook (max 140 Zeichen)
linkedinUrl: ''  # Nach Veröffentlichung ergänzen
---
```

### Neue Felder

| Feld | Beschreibung |
|------|--------------|
| `linkedinType` | `post` (Standard) oder `article` für Langform |
| `linkedinHook` | Manueller Override für die ersten 140 Zeichen (vor "See more") |

### Differenzierung type vs. linkedinStatus

| type | Bedeutung |
|------|-----------|
| `blog` | Primär für Website, kann auf LinkedIn gepostet werden |
| `linkedin` | Primär für LinkedIn, ggf. auf Website gespiegelt |
| `conference` | Konferenzbeitrag, PDF-Download |

| linkedinStatus | Bedeutung |
|----------------|-----------|
| `draft` | Noch in Arbeit, nicht veröffentlichungsreif |
| `planned` | Fertig, Veröffentlichung geplant |
| `published` | Auf LinkedIn veröffentlicht |

## Artikel-Template

```markdown
---
title: 'Serie #N: Titel'
description: 'Kurze, prägnante Beschreibung'
pubDate: YYYY-MM-DD
author: 'Andreas Sigloch'
image: '/images/xxx.jpeg'
tags: ['Tag1', 'Tag2', 'Tag3']
series: 'Serienname'
draft: false
type: 'blog'
linkedinStatus: 'planned'
---

## [Auslöser/These/Problem]

[1-2 Absätze: Was ist der Anlass? Warum ist das relevant?]

> **Kernthese als Blockquote**

## [Hauptinhalt]

### [Unterpunkt 1]
[Erklärung mit konkretem Beispiel]

### [Unterpunkt 2]
[Zahlen, Daten, Fakten]

*Tech: [Relevante Tools/Technologien]*

## [Fazit/Call-to-Action]

[1-2 Sätze: Was soll der Leser tun/denken?]

---

*[Weiterführender Link oder Kontakt-CTA]*
```

## Checkliste vor Veröffentlichung

- [ ] Titel enthält Seriennummer (falls Serie)
- [ ] Description < 160 Zeichen
- [ ] Mindestens eine Kernthese fett oder als Blockquote
- [ ] Konkreter Nutzen/Takeaway erkennbar
- [ ] Keine Marketingfloskeln
- [ ] Bild vorhanden (oder bewusst weggelassen mit Kommentar)
- [ ] 3-5 passende Hashtags definiert
- [ ] Kontakt-Link am Ende
- [ ] `linkedinStatus` korrekt gesetzt

---

## Veröffentlichungsrhythmus

**Empfehlung:** 1x pro Woche (Dienstag oder Mittwoch, 8-10 Uhr)

**Serien-Planung:**
- Alle Artikel einer Serie mit wöchentlichem Abstand planen
- Zwischen Serien: 1-2 Einzelartikel als Abwechslung
- Praxisbeiträge und Fachbeiträge abwechseln
